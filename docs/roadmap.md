# RunVoice Roadmap

## 已完成的阶段基础

- GPS 距离、配速、静止漂移与异常定位恢复
- BLE 心率、自动重连与固定阈值高心率提醒
- 公里、四分之一公里、闭环分段和耳机音量键播报
- 断电 checkpoint、原轨迹续写和主动暂存退出
- GPS CSV、摘要海报及公共 Documents 导出
- Room 跑步摘要历史表、按月历史列表和基础月汇总
- 单次详情、部分保存状态与私有文件安全删除

## 下一阶段

1. 历史列表轨迹缩略图
   目标: 让用户能凭路线形状快速辨认很久以前的一次跑步。
   实施边界: 复用历史记录中已有的海报或轨迹引用，在后台按需生成和缓存，不接入在线地图，也不影响实时记录链路。

2. 历史查询与趋势
   目标: 在已有按月列表基础上增加跨月查看能力。
   候选能力:
   - 日期范围筛选与关键词备注
   - 周跑量 / 月跑量趋势
   - 距离、时长与平均配速对比
   - 数据导出

3. 历史数据的重装与换机恢复
   目标: 卸载重装或更换手机后不再丢失跑步历史，同时不放宽现有的隐私姿态。

   背景: 当前卸载即丢。应用无账号无云端，`android:allowBackup="false"`，且备份规则排除了全部 domain。
   而公共 Documents 副本虽然能在卸载后存活，却已经位于应用沙盒之外，与上述姿态并不一致。

   已确认的约束（实测于 Xiaomi HyperOS / Android 16）:
   - 备份规则中的 `external` domain 指 `getExternalFilesDir()`，不覆盖 `/sdcard/Documents/`；
     关闭应用备份并不能阻止厂商整机备份带走公共副本。
   - 公共副本会被 MediaStore 索引，`run-<日期>-<时间>.csv` 的文件名本身即泄露作息。
   - 可用的设备标识只剩 `ANDROID_ID`（SSAID）。`Build.SERIAL`、IMEI、MAC 对普通应用均已不可读。
   - SSAID 按 (应用签名密钥, 用户, 设备) 分域，卸载重装不变，其他应用取到的值不同。

   分层方案（建议按此顺序落地，各层独立可用）:
   - 第一层 数据分级: 摘要（起止时间、时长、距离、平均配速、最大心率，不含位置）明文写公共目录，
     足以重建历史列表；精确轨迹点不再无条件写入公共目录。摘要文件名改用随机 ID，元数据移入文件内部。
   - 第二层 轨迹加密: 轨迹以随机数据密钥 DEK 加 AES-256-GCM 加密后再写公共目录。
     GCM 的认证标签同时承担完整性校验，密钥错误或文件被篡改会直接失败而非产出错误明文。
   - 第三层 多密钥槽: DEK 用信封加密，分别由设备密钥槽与用户口令槽各封装一份，任一可解开。
     设备密钥槽由 SSAID 派生，默认启用、零用户负担、覆盖卸载重装；
     用户口令槽可选，由口令经 PBKDF2WithHmacSHA256（迭代 ≥210,000）派生，覆盖换机与恢复出厂。
     新增密钥槽不需要重新加密既有数据。

   必须记录的风险: 设备密钥槽绑定应用签名密钥。当前发布使用 Android Debug 证书，
   若将来改用正式签名，SSAID 随之改变，仅有设备密钥槽的历史数据将永久无法解密。
   因此在切换签名密钥之前，必须先提供并引导用户启用口令槽，或提供一次性重新封装流程。

   实施边界: 不引入账号与云端；文件格式自描述并随项目提供独立解密脚本，保证数据不被应用锁定；
   不影响实时记录链路；口令一旦遗失不提供任何找回途径，需在设置时明确告知。

## 更后面的阶段

1. 即时训练分析
   目标: 在跑步过程中给出更有意义的训练状态判断。
   候选能力:
   - 心率区间（Zone）判断
   - 有氧 / 无氧提示
   - 基于年龄和目标区间的个性化上下限提醒
   - 节奏异常提醒

2. 历史分析能力
   目标: 从多次跑步数据中看趋势，而不是只看单次结果。
   候选能力:
   - 心率趋势
   - 配速稳定性
   - 恢复跑 / 训练跑分类
   - 周期训练对比

## 实施原则

1. 优先做“自用时最直接有价值”的功能。
2. 优先保证播报、心率和即时读数可靠，再扩展分析。
3. 先积累足够的真实跑步数据，再决定长期保存字段和训练指标。
4. 不以在线公共地图瓦片作为第三方流量依赖；地图能力优先考虑离线方案。
5. 写到应用沙盒之外的数据，一律假设同机其他应用可读、且会被厂商整机备份带走。
   位置等敏感字段要么不写入沙盒外，要么加密后写入。
